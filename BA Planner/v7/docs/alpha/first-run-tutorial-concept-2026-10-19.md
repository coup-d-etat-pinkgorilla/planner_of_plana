# 첫 실행·튜토리얼 구상 (2026-10-19, CM 초안 — CF 설계 입력용)

원칙: 별도 튜토리얼 페이지를 만들지 않는다. **빈 상태 화면이 곧 안내**가 되게 하고, 첫 실행 체크리스트 1개만 따로 둔다. 블루아카 UI 톤(사다리꼴 섹션·짧은 문장)을 유지한다. 모든 문구는 "지금 할 일 1개 + 왜" 두 줄을 넘기지 않는다.

## 1. 첫 실행 체크리스트 (모달 1개, 3단계, 건너뛰기 가능, 설정에서 다시 열기)
| 단계 | 화면 | 자동 확인 | 사용자가 할 일 | 실패 시 문구 |
|---|---|---|---|---|
| ① 게임 설치 찾기 | Steam 라이브러리에서 BlueArchive 폴더 자동 탐색 결과 + 경로 입력란 | `BundleRevision` 파일 존재, 카탈로그 파일 존재 | 못 찾으면 폴더 지정 | "설치 폴더를 못 찾았어요. Steam → 게임 → 관리 → 로컬 파일 보기 경로를 넣어 주세요" |
| ② 이미지 준비 | 진행 막대 + "아이콘 1,330개 준비 중" | 첫 실행 추출(명세대로) 실행, 결과 수·실패 수 | 기다리기 | "N개를 못 만들었어요. 스캔은 되지만 그림이 비어 보일 수 있어요 — 나중에 설정에서 다시 시도" |
| ③ 계정 만들기 | 기존 Title 계정 생성 섹션 재사용 | v6 `config.json` 발견 시 가져오기 제안 | 이름 입력 또는 v6 가져오기 | — |
- 끝나면 홈으로. 체크리스트 완료 여부는 사용자 데이터 경로에 저장(zip 교체해도 유지).
- 게임 패치 뒤 `BundleRevision`이 배포 스냅샷과 다르면 ②만 다시 띄운다(이미지는 재추출, 표 자료는 "새 버전 자료 필요" 알림 — 결정 B 연동).


## 1-A. 연습 계정 (사용자 추가 2026-10-19 22:09)
- 첫 실행 체크리스트 ③ 뒤, 또는 설정 어디서든 **"연습 계정 만들기"** 버튼. 이미 있는 개발용 시드 도구(`backend/tools/seed_ui_test_profile.py` — 독립 계정에 목록·계산 상태가 다른 8개 시나리오를 멱등 추가)를 **제품 기능으로 승격**해서 쓴다: 학생 확정 20명 안팎(등급·레벨·장비가 섞인), 인벤토리 일부 채움, 계획 1개 + 시나리오 1개, 전술 기록 2~3건, 스캔 이력 1건(저장된 fixture로 만든 "검토 화면" 상태 포함). 게임 없이도 모든 탭이 비어 있지 않게.
- 이름은 고정 `연습 계정`(아이콘에 표시), 타이틀 화면에서 구분되고, **한 번에 삭제** 가능. 내용은 멱등이라 "초기화" = 삭제 후 재생성.
- 연습 계정에 들어가면 상단에 얇은 **안내 띠** 하나만: "① 학생 탭에서 미카를 눌러 보세요 → ② 계획 탭에서 목표를 바꿔 보세요 → ③ 인벤토리에서 부족분을 보세요 → ④ 스캔 탭에서 저장된 스캔을 검토해 보세요". 현재 탭에 맞는 한 줄만 보이고, 다 보면 띠가 사라진다(닫기 가능). 하이라이트·강제 순서 없음.
- 스캔 탭만 특별: 연습 계정에서는 실제 캡처 대신 **저장된 스캔 세션 1건을 재생**해 검토·확정 흐름을 익힌다(스캐너 골든 fixture 재사용, 게임 불필요). 실제 스캔 버튼은 그대로 두되 "연습 계정에서는 저장된 스캔으로 연습해요" 한 줄.
- 연습 계정 데이터는 v6 가져오기·통계 집계·전술 추천에서 **제외 표시**(실제 계정 통계에 섞이지 않게). 백엔드에 `is_practice` 플래그 1개(FB 요청).
- 사용자 경로 3개(§3)를 연습 계정에서 먼저 하고 실제 계정에서 반복하는 것이 튜토리얼의 전부다.

## 2. 빈 상태 = 안내 (화면마다 1장)
| 화면 | 빈 상태일 때 보여 줄 것 | 행동 버튼 |

| 스캔 탭(스캔 0회) | "게임을 창 모드(1280×720 이상, DPI 100 %)로 켜고 학생 목록 화면을 여세요" + 창 인식 상태 표시(FB-4의 client_width/height·game 값 활용) | "창 찾기" → 스캔 시작 |

| 백엔드 미연결 | "계산 엔진이 아직 안 떴어요 (대개 5초 안)" + 재시도 | "다시 연결" |

## 3. 처음 쓰는 사람의 경로 3개 (UI 최종 검토의 테스트 시나리오이자 튜토리얼 범위)
1. 계정 만들기 → 학생 스캔 → 검토·확정 → 계획 1개 만들기 → 부족 재료 보기
2. 인벤토리 스캔 → 부족분 반영 확인
3. 설정 → v6 가져오기 → 계획 탭 확인
각 경로에서 "여기서 뭘 눌러야 하지?"가 나오는 지점만 안내 문구를 추가한다. 경로 밖 화면은 안내 없음.

## 4. 하지 않는 것
- 전체 기능 투어, 하이라이트 오버레이, 강제 순서 코치마크(연습 계정의 한 줄 안내 띠만 허용).
- 텍스트 긴 도움말 페이지(설정에 "도움말 → GitHub README 링크" 1줄로 대체).
- 영어 문구(알파는 한국어만; 설정 탭 영어 문구 FD는 CF 결정대로).

## 5. 검증 방법
- 결정 C의 테스터 1명이 경로 1~3을 안내 없이 수행. 막힌 지점 = 튜토리얼 수정 목록. 두 번째 사람이 막히지 않으면 완료.
- golden: 빈 상태 화면 7장을 golden에 추가(FE 레인).

## 6. 소유
- 연습 계정 생성·삭제·`is_practice`·저장 스캔 재생 = 백엔드(XB, FB 요청서), 안내 띠·버튼·빈 상태 화면 = CF.

## 7. 진행 방식 (사용자 결정 2026-10-19 22:18)
**화면 시안 먼저, 구현은 시안을 따라.** 기존 UI 아티팩트(시안) 워커 — `docs/frontend-redesign/prototype/2026-10-05/`의 artboard를 만들던 그 워커 — 와 함께 ① 첫 실행 체크리스트 3장 ② 연습 계정 안내 띠 상태 2장 ③ 빈 상태 7장 ④ 스캔 문제 신고 띠·버튼 1장, 총 13장 안팎의 artboard를 먼저 그린다. 그다음 CF가 평소대로 artboard 지도에 행을 추가하고 slice로 쪼개 구현한다. 이 문서는 그 시안 작업의 입력이다. slice 분할·FD 번호·artboard 대응은 CF가 정한다. 첫 실행 추출 ②는 M6 명세(`first-run-extract-spec.json`)가 나오기 전엔 현재 기준팩 생성 목록(아이콘 1,330)을 임시 명세로 쓴다.
