## 무기 레벨에서 폴백이 발생한 경로

모든 레벨 실패는 실제 1280x720 렌더였다. 11건은 Lv.30, 2건은 Lv.40이었다.

1. Studio 위치 셀은 화면 비율 좌표를 그대로 잘라 1280 화면에서 각 숫자가 약 16x17 픽셀로

   래스터였다.
2. 기존 마스크는 `RGB 최솟값 >= 185`인 밝은 픽셀을 선택했다. 작은 글자의 흰 내부와 밝은
   카드 배경이 붙으면서 실제 숫자 대신 6픽셀 조각만 남거나, 반대로 배경과 연결된 136픽셀
   컴포넌트가 남았다.
3. Lv.30은 Studio 결과가 `0, 9`로 시작해 선행 0 금지 규칙에서 불완전 판정됐다. Lv.40은
   `6, 9`, 최소 점수 0.495449와 최소 마진 0.001450으로 안전 gate를 통과하지 못했다.
4. 기존 전체 quad의 2분할 glyph 보조 판정도 각각 38과 48을 최상 후보로 냈지만, 마진이

   올바르지만, 장착 상태에서 레벨 또는 성급 중 하나라도 미확정이면
   `StudentMatcherAdapter`가 무기 상세 패널을 열어 두 필드를 최대 3회 다시 읽으므로 이
   레벨 거부가 공통 폴백으로 관측됐다.

## 구현

무기 레벨은 두 기존 digit 판정이 모두 거부한 경우에만 고정 64x48 quad 전체를 64x32 이진
특징으로 정규화하고, 이미 번들된 무기 레벨 1..60 전체 값 템플릿과 비교한다. 무기 필드의
기존 shadow 검증은 3/3 정답이었으므로 다른 숫자 필드에는 승격하지 않았다. 점수 0.49,
마진 0.01을 함께 요구한다. 재현 Lv.30은 값 30, 점수 0.503333, 마진 0.012394이고 Lv.40은
값 40, 점수 0.584843, 마진 0.035887로 통과한다. 관측 note에는 Studio 완성 여부·labels·
점수·마진과 기존 glyph 후보·점수·마진을 모두 남긴다.

무기 성급은 cyan 전체 bounding box의 폭/높이 비율을 폐기했다. 기존 방식은 무기 본체,
발광 마킹과 작은 태그 선을 별 픽셀과 합쳐 3개를 4.64개, 1개를 4.98개, 4개를 4.36개로
계산해 거부했으며, 다른 일부 실제 4성은 3성으로 확정하기도 했다. 새 방식은 ROI를
205x54로 정규화하고 우측의 항상 존재하는 별을 기준으로 33픽셀 간격의 네 슬롯을
오른쪽부터 비교한다. cyan 점유율 0.25..0.55, 활성 슬롯 IoU 0.65 이상, 다음 비활성 슬롯
IoU 0.45 이하를 요구하고 첫 공백에서 중단한다. 따라서 연결된 무기 cyan은 별 모양과
다르면 다음 슬롯으로 인정되지 않고, 별은 연속된 1..4 값만 확정된다.

무기 상세 폴백이 실제로 남는 경우에는 후보 evidence에 `weapon_level_fallback` 또는
`weapon_star_fallback`을 별도로 추가한다. 각 행은 기본 판정의 status/source/confidence/note와
상세 패널 결과 source를 함께 기록한다. 상세 판정이 기본 실패 관측을 덮어써도 어떤 필드가
왜 패널을 열었는지 사후에 확인할 수 있다.
